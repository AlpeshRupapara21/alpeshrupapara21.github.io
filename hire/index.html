Dialbridge Public repos

B2B masked-calling platform — API, admin console and three client SDKs

Role
Architect and full-stack engineer. Designed the platform and authored all four repositories.
Problem
Bridge two real phone numbers so neither party sees the other's number — while the callee's phone rings as an ordinary cellular call, with no app and no internet on their side. And do it without the integrator's secret key ever reaching a mobile binary.
Built
A Node/TypeScript API with a React admin console, and a three-SDK client surface: iOS (Swift Package Manager), Android (Kotlin, OkHttp + coroutines, distributed via JitPack) and a Node server SDK. A publishable SDK suite with documented install paths for SPM, Gradle/JitPack and npm — the kind of API surface a third-party developer can adopt without reading the source.

02

CallSieve Systems Swift

Ten million blocked numbers in a Call Directory extension, in 31 KB

Role
Author. Library, benchmark harness and documentation.
Problem
A CXCallDirectoryExtension is not an app — it is a short-lived process with a hard memory ceiling, and iOS kills it without explanation when it crosses the line. The obvious implementation, an [Int64] of every number, is 76 MB of dirty resident memory at ten million entries. The error tells you nothing about why.
Built
A succinct, memory-mapped phone-number set in pure Swift with zero dependencies. The benchmark harness runs one child process per measurement — because phys_footprint never falls back after a large allocation, so measuring both paths in one process would contaminate the result — and cross-checks itself by XOR-ing every number read, so a blob that silently dropped entries could not produce a flattering number.
Result
76.28 MB → 0.031 MB peak footprint at 10M clustered numbers — 10.7 bits per entry, 6.7M lookups/sec. The naive curve grows linearly; this one does not grow at all. That is a different curve, not a constant factor.
